A controlled run on BIRD: the same questions answered twice — once as SQL straight from the DDL, once as ConQuer‑92 over a reverse‑engineered ORM model.

Not merely equal in total — identical question by question. Both arms answered the same 17 correctly and the same 13 wrongly, across two databases of opposite character. Zero disagreements. The conceptual model neither helped nor hurt.

The cost is coverage. Those 30 are all that ConQuer’s implemented subset can express, out of 70. Over the whole 500-question benchmark the picture is the same: analytical questions are mostly computation over a result set, and this language navigates and filters but does not compute.

01 What was being tested

The project builds a ConQuer‑92 → SQL compiler that reads an ORM conceptual schema. Reverse engineering derives that schema from an existing database. The open question was whether the conceptual layer earns its place: does routing a natural-language question through a named, typed, fact-oriented model produce better queries than writing SQL against the raw DDL?

BIRD is the standard benchmark for this — 500 questions in the mini-dev split, each with a hand-written gold SQL query and an expert “evidence” note, over 11 SQLite databases. Scoring is execution accuracy: run the candidate and the gold query, compare result sets.

Protocol

  • Two databases, chosen for opposite character: california_schools (3 tables, wide and denormalised, questions dominated by arithmetic) and toxicology (4 tables, molecules/atoms/bonds, questions dominated by structural navigation).
  • Arm A written first, from the DDL and the question, without consulting the conceptual model. Arm B written afterwards, from the model’s vocabulary. Gold SQL was not read before either arm.
  • Every question ConQuer could not express was recorded with a reason rather than skipped, so coverage is measured rather than assumed.

This is not an artefact of the two databases. Across all 500 mini-dev questions the gold queries need the same things: 20% use LIMIT, 19% CAST, 18% CASE/IIF, 14% arithmetic in the projection, 11% GROUP BY, 10% date functions.

ConQuer‑92 is a navigational language: it walks fact types, filters, and compares. The report’s grammar does define scalar expressions, and the Common Core Model has an open function table — so this is a limit of the implementation, not of the language on paper. But it is the limit that decides the score.

Three of these five categories are properties of the benchmark rather than of either method. That is worth stating plainly: a meaningful part of the 43% error rate in both arms is the cost of guessing a convention, not of writing a query.

04 Two gaps the run exposed

Fixed during the run

Ring fact types were unreachable. The first toxicology pass scored 3/17. Eleven of the twelve failures were one cause: connected(atom_id, atom_id2) derives as Connected: Atom | Atom, and nothing in the query text could say which of the two roles was meant.

Appendix B.2 of the transcribed grammar has <role reference> ::= [<postfix>] <role name> for exactly this. It had never been implemented, and the reverse engineer was not naming roles at all. Implementing it took toxicology from 3/17 to 11/17.

Still open

There is no syntax for an optional traversal. Reading a role asserts the fact exists, so a question about schools that have no closing date returns zero rows. The Common Core Model supports it — a step carries join: "outer" — but the surface language cannot ask for it. This changed no score here only because the direct arm failed the same question for an unrelated reason.

05 What reverse engineering made of these schemas

BIRD’s databases are better keyed than the legacy schemas this tool was built against: all eleven declare foreign keys, and only three tables anywhere lack a primary key. The rule that fails silently on undeclared keys never fired.

One derivation is worth recording. In california_schools both foreign keys run primary‑key to primary‑key, so the heuristic reads frpm and satscores as subtypes of School — the vertical-partitioning trap, and it reports itself as a guess. It happens to be harmless for querying: sibling subtypes join on the shared identifier, so paths cross between them correctly. In toxicology the recursive many-to-many came out exactly right, as an objectified ring fact type.

06 Threats to validity

  • One model wrote both arms — and it is the author of the ConQuer implementation. There is no cross-model variance here. The clean per-question agreement is evidence against that biasing the result, but does not eliminate it.
  • The toxicology second pass was not blind. Arm B was revised after seeing which queries failed to compile; Arm A was written once and never revised. No query was changed after seeing a wrong result — only after a parse error — but the asymmetry is real, and 3/17 is the honest blind figure for that database.
  • n = 70, two databases. The coverage figure is corroborated by the feature profile over all 500 questions; the accuracy figure is not.
  • Arm A is not a serious text-to-SQL baseline. Published BIRD systems use schema linking, retrieval and self-correction. 57% overall is plausible for a single pass, but this is a comparison of two arms, not a leaderboard entry.

07 What this settles, and what it doesn’t

On analytical text-to-SQL, the conceptual layer does not earn its place. Given a question the language can express, routing through a named fact-oriented model produced exactly the same answers as writing SQL directly — and the model’s vocabulary cost 57% of the questions outright.

That is a narrow verdict, and it should not be read as a verdict on conceptual modelling. The errors that remained were about understanding the domain — that a column called “Percent” holds a fraction, that “atom 19” is a suffix convention, that “between A and B” is symmetric. A conceptual model with real predicate readings, value constraints and verbalisation is aimed squarely at those, and every reading in these models was the placeholder {0} has {1}, generated from column names, because a relational catalog records no verbs.

The test that would actually be informative: take a hand-refined model — predicates renamed, constraints added, units recorded — and re-run. That isolates the thing being claimed. This run only shows that a machine-derived model, on its own, adds nothing.
